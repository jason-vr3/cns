2核心算法：程序是怎么算的

整数部分：除基取余（倒序读）

不断除以目标进制 base，记下每次的余数，直到商为 0；把余数倒着拼起来就是结果。

10 (dec) → bin 10 ÷ 2 = 5 ··· 余 0 5 ÷ 2 = 2 ··· 余 1 2 ÷ 2 = 1 ··· 余 0 1 ÷ 2 = 0 ··· 余 1 倒序读 → 1010

对应代码里的 n % base 与 n // base 循环。

小数部分：乘基取整（正序读）

不断乘以 base，每次取走整数部分作为一位小数，用剩下的小数继续乘；取出的数字正着拼起来。

0.625 (dec) → bin 0.625 × 2 = 1.25 → 取 1 0.25 × 2 = 0.5 → 取 0 0.5 × 2 = 1.0 → 取 1 正序读 → .101

浮点数可能有精度误差，所以程序最多取 10 位小数。

其他进制 → 十进制：按权展开

每一位数字乘以 base 的对应次幂再相加，小数点后第 i 位（从 1 开始）权重是 base-i。

1A.8 (hex) = 1×16¹ + 10×16⁰ + 8×16⁻¹ = 16 + 10 + 0.5 = 26.5

4避坑笔记：函数里的变量作用域

这个项目踩过的最典型坑：在函数内部读写外部的变量。

Python 规定：只要函数体内出现过 new = ... 这样的赋值，new 在整个函数内就会被当作局部变量——哪怕那行赋值写在 if 分支里、根本没执行到。于是函数开头读 new 时就会报 UnboundLocalError。

反过来，函数参数改名成 new，但函数体里还残留旧名字 num，num 就会"逃逸"到全局作用域，引用到外面的字符串，导致 int('17.5') 这类 ValueError。

正确做法：函数需要什么值，就通过参数传进去（如 dec_to_msg(new)），函数内部统一使用参数名，不直接读写外部变量。
